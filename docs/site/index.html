What it takes care of.

Before the launch, and after it:

  1. 1

    Made for people who aren’t designers, all the way to a live address.

    Multiple-choice questions anyone can answer, then ideas drawn on your own name to point at, one of them always the classic, done beautifully. Then it publishes the site and checks it live.

  2. 2

    Ready to launch, not just good-looking.

    Before it hands over, it checks what going live needs: link previews, dead links, keyboard and screen-reader basics, speed, motion filmed over time, and the legal pages a German business needs. It fixes things until the audit says “Ready to ship”.

    The audit, before it hands over

    • Title, description and link previews
    • Every link, inside the site and out
    • Keyboard focus, contrast and axe-core’s rules
    • The weight of a first visit
    • Motion, filmed: nothing jumps, nothing loops forever
    • An Impressum and privacy page, where the law asks

    Ready to ship or it doesn’t go online.

  3. 3

    Easy to keep up to date.

    Hours, prices and events live in one place. “We’re closed on the 24th” is one sentence to your agent, and every change is saved.

One run, start to finish.

Kleiner Kaffee, a made-up café with eight seats in Saarbrücken. Everything the run showed along the way, in order.

  1. It asks.

    A few multiple-choice questions, then one message with whatever you have: a few lines, a menu, photos. No prompt to write.

    Answers: A small business · Warm · Pick colours for me · Gentle motion · Goal: visit · No extras

    “Kleiner Kaffee, 8 seats, Röstergasse 12, Saarbrücken … Roasts its own beans every Tuesday in a 5 kg drum roaster … No photos.”

  2. It thinks of three ideas.

    Before any code it writes a brief: facts only the café has, the one job of the site, and three ideas from different facts, all three warm. It recommends the classic, done beautifully: the roaster drawn large beside the headline, with the hours and the address under it.

  3. It shows three first screens.

    Around the kept idea it builds the top of the page three ways, at phone and desktop size, one of them always the classic. The café took A, the classic split. Real pictures come first, the owner’s or free ones; this owner said no photos, so the roaster is drawn.

  4. It looks, and a reviewer checks.

    It photographs every page at phone, tablet and desktop width, films how it moves, and fixes what’s wrong. Then a reviewer that didn’t build it names the three worst problems, and those get fixed too.

  5. It audits, then you point.

    The run only ends on “Ready to ship”. This is the café’s. Then you see the screenshots numbered, so “make 2c bigger” is enough.

    # Audit: Ready to ship.

    All clear.

    • axe-core on /, /impressum.html and /datenschutz.html: no violations.
    • /: first visit 111 KB (JS 1 KB, CSS 5 KB, fonts 54 KB gzipped)

  6. It goes online.

    It publishes where you say, after you say yes, and checks the live address. It leaves a short guide to changing things later.

Install one-shot-site

Three ways in. They all put the same folder where your agent looks for skills.

Any agent recommended

With npx skills, for Claude Code, Codex, Cursor and other agents.

{{site.install}}

-a claude-code (or codex, cursor) names your agent; without it, the skill can land in a folder for each of about 20 agents. Add -g to install it for every project instead of this one.

Claude Code plugin

Inside Claude Code, one line at a time:

/plugin marketplace add Barabosik/one-shot-site
/plugin install one-shot-site@one-shot-site

From a terminal it’s the same with claude plugin in front: claude plugin marketplace add Barabosik/one-shot-site, then claude plugin install one-shot-site@one-shot-site.

By hand

Copy one folder, skills/one-shot-site, from the repository:

git clone https://github.com/Barabosik/one-shot-site

Claude Code reads .claude/skills/ in a project and ~/.claude/skills/ for every project. Codex, Cursor, Gemini CLI and GitHub Copilot read .agents/skills/ and ~/.agents/skills/.

What happens next

  1. Open your agent in an empty folder. The site gets built there.
  2. Say “make me a website”. Or “redesign my site” with the link.
  3. Answer six or seven questions. Then send what you have: text, photos, a logo. “Skip, write it for me” works too.
  4. Pick an idea, then a first screen. Three of each, drawn with your own name and words, one of them always the classic.
  5. It builds and checks. Real pictures first: yours, or free photos of your kind of place. Then screenshots, a film of the motion, an audit. You see them numbered.
  6. You say where it goes. It publishes only after your yes, and leaves a short guide to changing things.

You need

  • Node 22.12 or newer, and git
  • Chrome, Edge, Brave or Chromium
  • An agent that runs shell commands. Built and tested in Claude Code; others should work but are untested.

Help make it better.

Start with an issue. A site it got wrong, a question that confused you, a check that missed something: open an issue with the answers you gave and, if you can, the brief from .one-shot/brief.md.

Pull requests are welcome after an issue, so we agree on the change first. Every pull request has to pass npm test on Linux, macOS and Windows. A change to how sites get built comes with the examples’ scores before and after.

What it needs, sends and costs

Does it need a server?

No. It makes plain static files: HTML, CSS, JavaScript, fonts and pictures, in plain Vite with no framework. Every file is yours. GitHub Pages hosts them for free from a public repository, and the tests cover that route. It also supports Vercel, Netlify, Cloudflare and your own domain, or it hands you the folder.

What leaves my computer?

The skill has no server and sends nothing on its own. The checks run in your own browser against a copy of the site on your machine. It goes online only to install packages from npm (Vite, axe-core, the fonts, and GSAP or three.js when an add-on needs them), to draw the looks with fonts from Fontsource (through cdn.jsdelivr.net), to search Openverse or Wikimedia Commons for free photos when you have none of your own (unless you say no) and download the ones you pick from the hosts they name, to open sites you name, to test the site’s outside links, and to publish, which it asks you about first. You log in to your host yourself; it never handles passwords or tokens. Your agent talks to its own model provider as usual.

How do I change it later?

Hours, prices and events live in one file, site.json. Tell your agent “we’re closed on the 24th”: it changes that one place, checks the changed screens, and publishes again. Every change is saved as its own commit, so you can take one back.

What does it cost?

The skill is free, under the MIT licence. Your agent costs what it always costs; a full run is a long session, because the agent looks at many screenshots. GitHub Pages hosts a site like this for free from a public repository (Netlify and Cloudflare have free plans; Vercel’s free plan is for non-commercial use), so a domain name is the only thing you might need to buy.

Which agents does it work with?

It’s built and tested in Claude Code. It uses the open Agent Skills format, so Codex, Cursor and other agents that can run shell commands can load it, but they haven’t been tested yet. Where the agent has a question picker, the questions come as one; elsewhere as a numbered list you answer with “2” or “1,3”.
